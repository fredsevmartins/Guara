# OpenTruth v0.1.2 — Scalable retrieval and safe cooperating clients

- Search and conflict checking now use SQL filters and bounded pages (default 100, max 1000).
  Search omits historical arrays by default; opt into them or inspect a claim explicitly.
- Schema 2 adds expression indexes transactionally, preserves historical entities/events/files,
  and keeps FTS synchronized through triggers instead of rebuilding it on every open.
- OS advisory locks serialize cooperating processes/threads, source operations, initialization,
  backup, and restore. Bounded waits expose WORKSPACE_BUSY; locks are released on process exit.
- MCP now offers twelve tools, including explicit claim revisions and evidence reassessment with
  reasons and attribution. Prior versions and assessments remain auditable.
- Frozen schema-1 workspaces and a backup generated by the actual v0.1.0/v0.1.1 implementations
  exercise data-preserving upgrades, archive compatibility, and migration failure rollback.
- An executable synthetic tutorial and a reproducible benchmark document complete workflows.
- A manual PyPI workflow validates a selected version tag and uses OIDC in a separate restricted
  environment. Registry publication requires maintainer Trusted Publisher configuration; it has
  not been performed or claimed. No new runtime dependency was introduced.

Local validation: 95 tests passed on Python 3.12.14/Linux, real MCP calls for all twelve tools,
Ruff, synthetic scenarios/tutorial, sdist/wheel builds, strict Twine metadata validation, dependency
checks, and the independently installed wheel workflow. Historical migration fixtures are included
in the sdist. The configured Windows suite now includes migration/concurrency tests; remote
cross-platform status is not confirmed because api.github.com remains blocked by the proxy.

Compatibility: clients previously expecting unbounded search/conflict responses must paginate.
Python get_claim_history retains its unbounded default; MCP history defaults to a page of 100.
Full inspection remains available on demand. Backup format remains 1 and accepts schema 1–2;
older applications cannot read upgraded schema-2 stores. Back up before upgrading.

One local 5,000-claim synthetic observation measured a 25-record page in about 1.5 ms; no timing
threshold, universal speedup, coverage percentage, or production concurrency guarantee is claimed.
Direct SQL/filesystem mutations and distributed/network-filesystem writers remain unsupported.
