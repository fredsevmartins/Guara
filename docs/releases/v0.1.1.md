# OpenTruth v0.1.1 — Backups, integrity, and explainable comparisons

- Complete backups combine a consistent SQLite snapshot with registered source files and a
  versioned SHA-256 manifest. Restore validates all contents into an absent data directory, never
  overwriting existing evidence. Bounded extraction rejects traversal, duplicate members, tampering,
  unsupported versions, and database integrity failures.
- `opentruth source verify` reports intact, changed, missing, unsafe, and metadata-only sources.
  The new `verify_sources` MCP tool brings the server to ten tools. Byte integrity never establishes
  scientific verification or changes a source's independent verification status.
- Numerical results now expose converted values, unit factor, absolute difference, applied
  tolerances, and the comparison rule. Non-finite explanation values are explicitly marked.
- Optional engineering, experiment, and study context checklists report missing fields and refuse
  comparisons with incomplete or mismatched selected templates.
- The CLI accepts positional claim text, common field flags, source titles/files, identifiers,
  and optional readable output. Existing JSON input/output remains compatible.
- CI covers Python 3.11–3.13 on Linux/macOS/Windows, with an independent installed-wheel smoke test.
  Windows runs the portable metadata/CLI/MCP suite; secure local source ingestion remains POSIX-only.
- A tag-triggered workflow creates the GitHub Release with wheel/sdist artifacts only after all
  matrix jobs pass. No PyPI publishing or new runtime dependency is introduced.

Local validation: 81 tests passed on Python 3.12.14/Linux, including all ten MCP tools, full source
backup/restore, malformed and tampered archives, and persistence. Ruff, four synthetic scenarios,
package builds, dependency checks, workflow YAML parsing, and the independent wheel workflow passed.
Remote CI and GitHub Release status require separate confirmation; GitHub API access from the
onboarding environment remains blocked by the network proxy. No coverage percentage or local
macOS/Windows execution is claimed.

Database schema remains version 1. Existing claim payloads are supported; optional context
checklists do not rewrite historical records. JSON export remains metadata-only. Backup format 1
is a separate complete archive, not a JSON import mechanism. See the backup, context, platform,
and validation guides for limits and compatibility details.
